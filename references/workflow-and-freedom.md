# Workflow, freedom, and approval depth

## Priority when guidance conflicts

Resolve conflicts in this order:

1. Safety, privacy, authorization, and destructive-action boundaries
2. Product truth and evidence
3. Usability, accessibility, and responsive operability
4. The user's explicit current request
5. The project's established brand and technical constraints
6. The selected creative-freedom mode
7. Skill recommendations
8. Examples and lessons from earlier projects

Historical examples are evidence, not universal design laws.

## Freedom-mode prompt

Ask only for new pages and substantial redesigns when the answer has not already been established:

> 这次希望我按哪种创作自由度推进？我推荐“引导模式”：先确认文案叙事和必要面板，其余视觉与动效由我自主设计；真实性、移动端、可访问性和运行时验证始终是硬要求。

- **自主模式** — one compact brief; pause only for material product ambiguity.
- **引导模式** — two approvals: copy/narrative, then module/state/mobile plan.
- **严格模式** — add visual-direction, responsive-wireframe, motion-contract, and pre-release gates as risk requires.

Do not ask again for a local correction. Revisit the mode only when scope changes from iteration to redesign or the user explicitly changes it.

## Grill-lite questioning

Ask a question only when all are true:

- repository evidence cannot answer it;
- different answers materially change narrative, modules, or product behavior;
- a reasonable default would risk meaningful divergence.

Ask one question at a time and offer a recommendation with its tradeoff. After an answer, test one level deeper for contradictions. Stop when these decisions are sufficient for the selected mode: audience, primary action, core promise, trust barrier, evidence boundaries, module inventory, motion emphasis, and mobile priority.

Do not ask “which sections do you want?” Investigate, propose a justified module inventory, then ask the user to approve, remove, reorder, or change it.

## Decision record

Before substantial implementation, keep a compact project-local brief using an existing project convention when available:

```md
# Landing brief

## Working mode
## Audience, promise, and primary action
## Evidence and claim boundaries
## Approved copy and narrative
## Module inventory
## Responsive transformations
## Interaction and motion contracts
## Acceptance matrix
## Deferred ideas
```

Do not create process files for tiny edits. The record prevents rediscovery and contradictory implementation; it is not ceremony for its own sake.
