# Stage C：风格方向库与结构推导

风格不是从模板开始的，是从"设计读取（Design Read）"开始的。本参考提供：先推导再选方向的判据、四个完整风格配方、以及结构推导流程。**配方是出发点不是终点**——最终 token 必须被项目的调性信号（见 discovery-and-brief.md A3）改写过。

---

## C1. 设计读取（Design Read）

写码前用一句话回答："这个项目在世界上的气质是什么？"例如：

- skilldo："一个把散乱收进秩序的工具，工程可信，带一点引力般的酷。"
- 清理类 CLI："安静、可靠、不装腔作势的管家。"

由这句话推导三个量化值（0–1）：

| 值 | 0 | 1 |
|---|---|---|
| design variance（版式变化度） | 每屏同构、极规整 | 每屏异构、张弛大胆 |
| motion intensity（动效强度） | 只有 hover/淡入 | 滚动编舞 + 物理模拟 |
| visual density（信息密度） | 大留白、一屏一事 | 高密度、表格/矩阵 |

三个值决定你从下面配方里取多少、改多少。

## C2. 四个风格配方

### 方向 1：终端美学（Terminal）

**适用判据**：CLI/agent 工具，受众是开发者，产品证据里有真实命令输出。调性信号偏工程。

**Token 集**（起点值，须被项目 logo 色改写）：

```css
--bg: #0B0E14; --panel: #11151F; --ink: #E6EDF3;
--muted: #8B949E; --subtle: #161B26; --border: #21262E;
--accent: <项目 logo 主色，如 #78F2C2>;
--accent-soft: color-mix(in srgb, var(--accent) 14%, transparent);
--radius: 8px;  /* 终端卡片略小圆角，内部行内元素 4px */
```

**字体搭配**：正文系统栈；标签/命令/数字用 `ui-monospace`（大写 + letter-spacing .1em+ 的 mono 小标签是 dev-tool 感的核心）；标题可用系统 sans 的 700 但避免引入第二显示字体。

**几何语言**：直角偏多、边框 1px、面板用背景色差异而非阴影分层；点缀性的角标/扫描线可以有，但每页 ≤2 处。

**结构暗示**：hero 左文右终端 mock；证据=真实输出、命令、表格；CTA=可复制的命令或 prompt。

**自检**：如果去掉配色后它和任何 CLI 工具官网没区别，说明差异化没做——问题通常出在终端内容不真实或结构没跟叙事弧走。

### 方向 2：编辑排版风（Editorial）

**适用判据**：内容型/文档型产品，叙事以理念为主，证据以文字与少量图为主；调性信号偏人文、克制。

**Token 集**：

```css
--bg: #FAFAF7; --panel: #FFFFFF; --ink: #1A1A1A;
--muted: #666; --accent: #B4441C;  /* 砖红/墨绿类油墨色，忌紫 */
--radius: 2px; --border: #E5E2DA;
```

**字体搭配**：衬线显示字体做 h1/h2（中文可用宋体系，英文 Georgia/衬线系统栈），正文无衬线；尺寸对比要拉到 4× 以上（如 h1 clamp(2.5rem, 6vw, 4.5rem) vs 正文 1rem）。

**几何语言**：细分隔线（1px）+ 大量留白（区块 padding ≥ 96px）；编号用小号衬线斜体；几乎不用卡片，用栏线和缩进组织信息。

**结构暗示**：大标题开篇 → 双栏正文 → 引文式证据 → 极简 CTA。动效只保留淡入与下划线延伸。

**自检**：留白是否敢留到位（新手最常见的失败是把编辑风做挤了）。

### 方向 3：Bento 信息拼版（Bento）

**适用判据**：能力多而平行的产品（矩阵型价值），需要一屏内高密度展示；调性信号偏现代、产品化。

**Token 集**：

```css
--bg: #F4F5F7; --panel: #FFFFFF; --ink: #111418;
--muted: #5C6670; --accent: <项目主色>;
--radius: 16px; --border: #E4E7EB;
```

**字体搭配**：单一无衬线家族靠字重与字号分层；数字/计数用 mono 强化"指标感"。

**几何语言**：卡片=信息单元，尺寸差异承载权重（重点卡 `span 2`）；圆角统一、阴影极轻（`0 1px 2px`）；**卡片间距必须统一**（gap 16–20px，不一致立刻廉价）。

**结构暗示**：hero（可窄）→ bento 矩阵（4–7 张卡，其中 1–2 张 span 2/带交互）→ 表格或对比 → CTA。≤960px 两列、≤640px 单列且 span 取消。

**自检**：每张卡是否只承载一件事？有没有卡在为了凑网格而存在？（凑数卡 = AI 味重灾区）

### 方向 4：沉浸叙事风（Immersive）

**适用判据**：产品有一个可物理化的核心隐喻（收拢、汇聚、流动、生长），受众允许被打动而不只是被说服；motion intensity ≥0.6 的项目。skilldo 落地页即此方向。

**Token 集**：从产品主题反推——深空类用 `--bg:#07090D` 类近黑 + 高饱和单一 accent；自然类用米白 + 有机色。**只有一束光**：全页只有一个 accent，所有戏剧性留给构图与动效。

**字体搭配**：正文常规；hero 标题可以放大到 `clamp(2.8rem, 8vw, 6rem)` 并配极轻字重，制造"空间感"。

**几何语言**：非对称、大面积负空间、元素可出血到屏幕外（暗示世界比视口大）；背景可有渐变光晕但每页 ≤2 处。

**结构暗示**：强宣言式 hero（一句话+一件正在发生的事）→ 逐屏展开证据（每屏一种构图，异构是本方向的生命）→ 终章 signature moment → CTA 收束。

**自检**：滚动是否像在读一个故事而不是刷一份 PPT？每一屏的构图有没有重复？

### 混合原则

允许"方向 4 的叙事骨架 + 方向 1 的证据语言"这类组合，但**视觉 token 只能归属一个家族**（不能用编辑风的衬线标题配 bento 的 16px 圆角卡）。混两个以上的家族必然失控。

## C3. 结构推导流程（判据，不是查表）

不要查"产品类型→页面结构"表。按此流程推导：

1. **取叙事弧**（Stage B 产出的 4–6 步）。每一步 = 一屏或半屏。
2. **给每步选证据形态**：这一步要消除的怀疑是什么？→ 能力怀疑给实拍/终端输出；机制怀疑给图解/动画；价值怀疑给数字/对比；安全怀疑给开源地址/文档。
3. **给每步定构图**：同一构图不得连续出现两次（section-layout repetition ban）。在"左右分栏 / 全宽宣言 / 网格 / 表格 / 时间线 / 出血大图"里轮换，且轮换节奏服务叙事（证据密→疏→密）。
4. **CTA 埋点**：叙事弧的收束点放主 CTA；中途若有天然停顿点（一个怀疑被消除后）可放次级 CTA，但全页主 CTA 只有一种动作。
5. **过反默认清单**：dark terminal + marquee + 编号分区 + bento + 三等分卡，这五件套若同时出现且无叙事理由 = 推倒重排。eyebrow 每 3 个 section 最多 1 个。

### CTA 形态从语境推导

“全页主 CTA 只有一种动作”不等于“所有入口都复制同一个按钮”。页头、hero 和终章的任务不同，形态也应不同：

- **页头**：是导航出口，优先紧凑文字链接、符号或细线反馈，不要抢过页面内容。
- **Hero**：可以使用页面中最强的操作控件，但其颜色、几何和层级必须来自 Design Read，而不是默认蓝/紫实心圆角矩形。
- **终章**：是叙事收束，可用编辑式动作链接、大号文字或方向性符号，避免再复制 hero 按钮。

判断“AI 默认按钮”的信号：高饱和实心色 + 中大圆角 + 白色粗体 + 蓝/紫阴影，并在多个视口重复。这个组合不是绝对禁止，但必须有品牌或交互理由；否则换成字体、细线、间距和方向符号建立层级。

## C4. 落地清单

- [ ] Design Read 一句话 + 三个量化值已写下
- [ ] 方向（或组合）已声明，token 被项目主色改写
- [ ] 每屏对应叙事弧一步，无"孤儿屏"
- [ ] 构图无连续重复，反默认清单已过
- [ ] 页头 / Hero / 终章 CTA 同一意图但形态有层级，未机械复制实心圆角按钮
- [ ] 浅/深双主题逐变量对照过对比度（正文 ≥4.5:1）
