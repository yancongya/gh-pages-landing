# Stage D：动效编舞

动效不是装饰，是叙事的第四维。本文覆盖：意图分类、分幕脚本方法、signature moment 设计法、技术选型、以及工程硬坑。

---

## D1. 动效意图与状态变化

每个动效必须回答“它在帮访客理解或完成什么”。下面四类是常见判断框架，不是封闭清单：

| 意图 | 作用 | 常见场景 |
|---|---|---|
| **orient（定位）** | 告诉访客"你现在在哪"、"上面还有什么" | 页头固定、滚动指示器、breadcrumb 式导航 |
| **reveal（揭示）** | 按叙事节奏逐步展示信息 | 淡入、滑入、终端逐行打出、数字滚动 |
| **compare（比较）** | 让两个状态的差异可见 | 切换主题、before/after、开关交互 |
| **confirm（确认）** | 让用户知道操作已生效 | 按钮点击反馈、复制成功提示、toast |

产品过程还可能需要表达 causality（因果）、progress（进度）或 continuity（持续运行）。纯装饰不是绝对禁止，但必须克制，不能争夺信息层级、损害性能或可访问性。

## D2. 分幕脚本

在实现前，写一张分幕脚本表。每行一个场景：

| 幕 | 内容 | 目的 | 触发 | 初态→终态 | 时长/曲线 | 重播/循环 | 离屏 | 手机 | reduced motion |
|---|---|---|---|---|---|---|---|---|---|
| 1 | Hero 文字入场 | 建立层级 | 页面加载 | 下移淡出→原位可见 | 0.6s ease-out | 不重播 | 保持终态 | 缩短位移 | 直接显示 |
| 2 | 数据流 | 解释信任边界 | 进入视口 | 密文包移动→本地解码 | 4s linear | 有间隔循环 | 暂停 | 缩短路径 | 静态终态 |
| ... | ... | ... | ... | ... | ... | ... |

**降级列是必须的。** 三类降级场景：

1. **`prefers-reduced-motion: reduce`**：所有动画时长归零、位移归零、opacity 直接到终态。不要隐藏内容——只是不动画。
2. **无 JS 环境**：CSS 动画保留（它们不依赖 JS），但 GSAP/Three.js 驱动的动效需要静态等价物。
3. **移动端 matchMedia**：重动效（物理模拟、pin、Three.js）在 ≤768px 降级为简单淡入或静态构图。

`reduced-motion` 不只是用 CSS 把 duration 设为零；JavaScript 也不应启动定时器、循环、字符变化或持续状态切换。直接渲染稳定终态。

### 渐进增强底线

核心内容在 CSS 中默认可见。只有在 JavaScript 成功初始化动效驱动后，才给 `html` 添加例如 `.motion-ready` 的状态类，并在该类下定义 reveal 初态。否则脚本异常、禁用 JS、不支持 `IntersectionObserver` 或全页截图都可能产生大段空白。

## D3. Motion hierarchy 与 signature moment

通常设置一个主要签名时刻——访客关掉页面后还能记住的那个画面。若多个独立产品机制都必须动态证明，可以有多个强场景，但要错开出现、区分强弱，并避免同时自动循环。设计方法：

1. **找叙事弧的高潮**：不是第一屏，不是 CTA 前——是"怀疑被彻底消除"的那一屏。
2. **回答四问**（同 discovery-and-brief.md B4）：
   - 隐喻：产品的哪个抽象概念变成了可见物理？
   - 时机：第几屏、第几秒？
   - 不可截图性：必须依赖滚动/时间才能体会吗？（如果是，静态降级也要好看）
   - 成本：什么技术栈？移动端等价物？
3. **给它最好的资源**：签名时刻可以比其他场景多花 3 倍开发时间，多用 100KB 代码。它是页面的全部记忆点。

### 动效预算不能平均分配

一个页面可以有多个动态证明面，但不要让它们拥有相同的视觉权重。如果 hero、终端、数据流和卡片同时自动循环，它们会互相削弱。将支持场景降为一次性解释、短状态过渡或用户触发的反馈。循环只用于表达持续过程，并在离屏时暂停。

### Entry, exit, replay, and loop contract

每个动态模块都要明确：

- **Entry:** 用户何时能看到初态，动画何时开始；
- **Exit/re-entry:** 离开视口后保持终态、重置还是再次进入时重播；
- **Replay:** 用户能否主动重跑，快速滚过后是否还有机会看到；
- **Loop:** 循环是否代表真实的持续状态，循环之间是否有呼吸间隔；
- **Offscreen:** 离屏后暂停计时器、观察器和持续动画；
- **Stable end state:** 无论动画是否执行，内容都处于可理解状态。

### 实例剖析：skilldo 黑洞终章

| 四问 | 答案 |
|---|---|
| 隐喻 | "45 个工具的 skill 被引力收拢进一个 hub" |
| 时机 | 最后一屏（叙事弧收束位，所有能力证据展示完毕后） |
| 不可截图性 | 中等——静态时要呈现"汇聚成一点"的构图，动图传达 70% |
| 成本 | GSAP ScrollTrigger pin + matchMedia（桌面限定），移动端给静态汇聚构图 |

## D4. 技术选型

| 需求 | 首选 | 升级条件 |
|---|---|---|
| 简单 reveal、hover、状态反馈 | CSS `transform` / `opacity` / Web Animations API | 不需要 |
| 滚动叙事、pin、编排 | GSAP + ScrollTrigger | 有明确叙事弧需要精确时序控制 |
| 物理模拟（引力、弹簧、粒子） | GSAP（内置 ease）或 Three.js | 核心隐喻需要物理感 |
| 3D / 数据可视化 | Three.js | 代表真实产品且有静态降级 |

**原则：先 CSS，不够再 GSAP，极少用 Three.js。** 每引入一个库，问自己：它带来的叙事价值是否值得它的体积和维护成本？

### 库使用规范

- 版本锁定（`@3.12.5`，不用 `@3`）
- `defer` 加载，放 LCP 之后
- SRI 哈希（CDN 脚本）
- 保留 HTML/CSS 降级
- 尊重 `prefers-reduced-motion`
- 排除 LCP 元素

## D5. 工程硬坑（实战经验）

以下是从 skilldo 落地页开发中总结的工程陷阱，每条都有真实案例：

### 1. i18n 双渲染路径

含 HTML 标签的文案（`<b>`、`<code>`、`<a>`）必须用 `data-i18n-html`（innerHTML）渲染；纯文本用 `data-i18n`（textContent）。两种属性必须在同一代码路径上并行处理——遗漏任何一种都会导致一端显示标签原文。**审计方法：grep 所有 `data-i18n` 和 `data-i18n-html`，确认无遗漏。**

### 2. translate = 目标 − 原点

GSAP 动画中 `y: 80` 意思是"从当前位置往下移 80px"，不是"移到 y=80"。如果元素初始有 margin/padding/flex 偏移，聚合动画会散开而不是汇聚。**修正：先用 `gsap.set` 测量或重置初始位置，再写相对位移。**

### 3. `gsap.set` 不可写在 defer CDN 之前的内联脚本

`gsap.set()` 必须在 GSAP 库加载之后调用。如果放在 `<script>` 内联块且 GSAP 是 `defer` 加载的，`gsap` 变量不存在，`gsap.set` 静默失败，所有元素叠在原始位置（看起来"动画没触发"）。**修正：GSAP 初始化代码放在库加载后的回调或 `DOMContentLoaded` 里。**

### 4. Lenis 接管后须用 `window.__lenis.scrollTo`

Lenis 接管平滑滚动后，原生 `window.scrollTo` 不再生效。代码中必须用 `window.__lenis.scrollTo` 或 Lenis 实例方法。`gsap.matchMedia` 的 `refresh()` 在路由/视口变化后要手动调用，否则 ScrollTrigger 的 pin 位置计算错误。

### 5. pin 要 pin 有背景的整节

`ScrollTrigger.pin` 会固定元素在视口，但被 pin 的元素必须有自己的背景色/背景图，否则滚动时下层内容会从透明处透出来。**检查：pin 目标元素是否有 `background-color` 或 `background`。**

### 6. `gsap.matchMedia` 限定桌面端

重动效（pin、物理模拟、Three.js）必须用 `gsap.matchMedia` 限定在 `min-width: 769px` 下运行。移动端不执行 GSAP 但保留 CSS 淡入作为降级。这样做的好处：移动端不加载 GSAP 逻辑，性能更好；`prefers-reduced-motion` 也可以在 matchMedia 里统一处理。
